## 0. 一页纸摘要

- **一句话介绍：** 比勒加群岛被万年一遇的风暴重创，玩家作为群岛的开创者与领导者，用 10 天时间收集散落物资、找回幸存居民、重建三座岛的基地，并在每个夜晚与居民一起抵御来自深海的敌人。
- **类型：** 塔防 / 策略 / RPG（轻量角色成长与装备）
- **平台：** 浏览器（Godot Web 导出，部署于魔搭创空间）
- **单局时长：** 10 天 ×（白天 100 秒 + 转场 2 秒 + 夜晚 80 秒）= **1820 秒 ≈ 30.3 分钟**
- **核心体验：** 科技长期规划 vs 居民即时调度；资源生产与防御投入的取舍；多岛同时受袭时"玩家只能站一座岛"的取舍。
- **比赛版范围：** 3 座岛；主岛 1→4 级，两个副岛各 1→2 级；10 天 10 夜，第 10 夜为最终夜（BOSS）；3 类居民 + 英雄；科技树与居民树各 6 节点 + 3 个协同点；**高塔是唯一的塔类建筑，最多驻 3 人，形态由驻守兵种决定**；第 5 级起引入**电力容量**；**全部 11 种建筑都有明确占地面积**。
- **两条路线的身份：**
  - **全科技流** = 强化自己 + 无人设施。玩家本人变成战斗机器，快速清场、快速巡视。
  - **全居民流** = 强化人口。能让一座岛上堆出 8 名战斗居民 + 1 名英雄，靠人墙而非塔。
- **核心张力：** 你在主岛战斗时，副岛正在失血；通讯告诉你情况，但支援要花 7 秒航程。
- **明确不做：** 居民死亡、多岛夜晚画面双线、开放世界、跨岛物流运输系统。

## 2. 游戏创意与定位

### 2.1 背景与主题

- **世界观一句话：** 比勒加群岛被万年一遇的风暴重创，玩家作为该群岛的开创人和领导者，白天收集散落的物资、寻找存活的居民、重建岛上的各种设施，夜晚和居民一起抵御来自深海的敌人。
- **叙事基调：** 玩家不是"孤身幸存者"，而是"重建秩序的人"。
- **与比赛主题的契合点：** 无指定主题。

### 2.2 玩家幻想

- **玩家扮演：** 一位伟大且强大的领导者。
- **玩家想获得的感觉：**
  1. 从废墟到充满生机的可见成长；
  2. 每一次白天防御布局的投入，晚上（或第二天）就能看到回报；
  3. 在三座岛之间奔走、判断"哪座岛更危险"的指挥感。

### 2.3 设计支柱

1. **白天准备，夜晚防御，节奏清晰。**
2. **科技是长期规划，居民是即时调度。**
3. **资源保持缺口，必须取舍。**
4. **玩家只能操控自己扮演的角色。** 多座岛同时受袭时，玩家是防守资源的一部分，不是万能钥匙。
5. **防线是你自己建的，也是你自己站上去的。** 高塔空着只是一段墙，站上谁、站几个人，它就变成什么强度的什么塔。
6. **失败有代价，但不羞辱玩家。** 失败进 BE，可读档重来；副岛失守可收复，不是终局。

### 2.4 反支柱

- 不做居民好感和死亡。
- 不做多岛夜晚**画面**双线操作（要数据双线，不能画面双线）。
- 不做复杂剧情分支和开放世界。
- 不做跨岛物流运输系统（资源全局共享，见 6.3）。
- 不在第 3 周后新增系统。

### 2.5 三条路线：只能完全解锁一方

两棵树并行。**两棵树在 2、3、4 级各有一次交汇，产生协同 Ⅰ / Ⅱ / Ⅲ**（见 7.6）。

**关键数字：** 每棵树点满需要 **30 研究点**；一局可获得的**全部研究点恰好是 30 点**。

> **因此整局只能完全解锁"三方"中的一方：**
> - 科技树 6 级（30 点）→ 居民树零投入 → **全科技**
> - 居民树 6 级（30 点）→ 科技树零投入 → **全居民**
> - 科技 4 级（15）+ 居民 4 级（15）= 30 → **混合**（三条协同全拿，但两棵树都没法满级）

| 路线 | 研究点分配 | 身份 | 终局形态 |
|---|---|---|---|
| **混合（一周目推荐）** | 科技到 4（15）+ 居民到 4（15）= **30** | 三条协同全拿，三种高级塔形态全能做 | 均衡；但没有 5/6 级的电力/英雄 |
| **全科技** | 科技 6 级 = **30** | **强化自己 + 无人设施** | 强玩家 + 电力自动化防线 |
| **全居民** | 居民 6 级 = **30** | **强化人口** | 单岛 8 战斗居民 + 1 英雄的人墙 |

**三条铁律：**

1. **协同 Ⅰ（通讯兵）需要科技 2 + 居民 2，即 6 个研究点。** 三条路线里**只有混合流会走这一步**；全科技与全居民把 30 点全压在一棵树上，**没有通讯塔，全程盲打**，靠"每座岛都能自己扛住"来弥补。
2. **两树 1 级默认开启。** 路线差异从 2 级开始。
3. **全押路线可通关，且不依赖随机**：关键人口来自确定性来源（6.11.4）。

**一周目的叙事引导混合流**：第 1—2 天的新手指引明确提示"科技与居民都要抓"；第二次游玩时结算界面再推荐另外两条路线。

### 2.6 独立性铁律（硬约束）

**科技树 5/6 级、居民树 5/6 级、协同 Ⅰ/Ⅱ/Ⅲ 三者内容互相独立，整局游戏三方只能完全解锁一方。**

| 禁令 | 说明 |
|---|---|
| **协同只负责"人"，不负责"物"** | 协同 Ⅰ/Ⅱ/Ⅲ **只解锁兵种与对应的高塔形态**。不提供任何建筑、资源、电力、人口、射程或伤害加成。 |
| **5/6 级只负责"物与己"，不负责"人"** | 科技 5/6 级只提供建筑 / 系统 / 玩家自身加成；居民 5/6 级只提供人口 / 上限 / 奖励倍率 / 英雄。**不得新增或修改任何兵种、任何高塔形态。** |

**三条由此派生的具体规则（防止旧关联复活）：**

1. **不存在"无人版的协同塔形态"**（例如自动迫击炮阵列）——那等于用科技替代协同。
2. **高塔（含所有协同形态）不耗电。** 电力只服务于科技 5/6 级自己的设施。
3. **英雄不可驻守高塔。** 英雄是居民 6 级的产物，兵种是协同的产物；英雄上塔会让两条线交叉。

## 3. 核心玩法循环

### 3.1 一句话核心循环

**白天：** 在主岛醒来 → 采集 → 找建造居民下达建造 → 修复 → 升级基地核心 → 点科技树/居民树 → 调度居民（含上塔）→（第 2 天起）出海探索副岛 →（若昨日有岛失守）清剿残敌并收复 → 入夜。
**夜晚：** 有基地核心的岛同时受袭 → 玩家在其中一座实时战斗 → 通讯（协同 Ⅰ 解锁）传来另外两座的情况 → 决定是否交通过去支援 → 清空波次后可继续采集与建造 → 80 秒结束进入结算。

### 3.2 循环拆解

| 阶段 | 玩家做什么 | 系统反馈 | 时长 |
|---|---|---|---|
| **白天** | 采集、下令建造、修复、基地升级、调度居民与上塔、点树、跨岛移动、清剿昨日残敌 | 资源与库存变化、建造进度条、居民工作动画、夜幕倒计时 | **100 秒（硬计时，不可提前结束）** |
| **入夜转场** | 仍可操作（移动/采集/修复，不可建造/拆除） | 镜头拉远、天色转为深蓝、敌方来袭方向提示 | 2 秒 |
| **夜晚前半** | 在所在岛实时战斗；通过通讯监控其他岛；决定是否交通支援 | 受击、击杀、核心与设施血量、状态标签 | 波次存在时（通常 40—70 秒） |
| **夜晚后半** | **波次清空后该岛即安全**，可继续采集、建造、修复（**不可拆除**） | 与白天相同的采集与建造反馈 | 直到 80 秒结束 |
| **结算** | 查看分岛损伤、失守判定、完美防御判定、维修消耗 | 结算面板（覆盖在新一天场景上，游戏暂停） | 玩家自行继续 |
| **下一日** | 天数 +1 | 进入白天 | — |

**关键规则：**

- **白天没有黄昏阶段。** "黄昏"只是白天最后 20 秒的画面氛围，**不产生任何阶段切换**。
- **夜晚不可跳过、不可提前结束。** 固定 80 秒。
- **夜晚清空波次后不会立刻结束**，剩下的时间仍是可操作的白天式时段。
- **夜晚禁止拆除建筑**，但允许建造与修复。
- 单局时长 = 10 ×（100 + 2 + 80）= **1820 秒 ≈ 30.3 分钟**。

### 3.3 一天内的推荐动作顺序（新手引导用）

1. 看 HUD 四资源 + → 缺什么采什么
2. 找建造居民 → 补上一夜损坏的城墙/高塔
3. 决定资源花在"经济（仓库/住房/升级）"还是"防御（塔/城墙）"
4. 把居民分配到高塔上（谁站上去、站几个，塔的强度就变）
5. 若有副岛告急风险 → 提前出海
6. 入夜；清空波次后继续用剩余夜晚时间补建

## 4. 胜负与结局

### 4.1 判定口径

- **岛屿损伤率** = `(1 − 当前非防御设施总 HP / 非防御设施总 HP 上限) × 100%`
  - 只统计**非防御设施**（基地核心、仓库、居民住房、码头、自动发电厂、自动采集机、自动维修机）。
  - 防御设施（城墙、路障、高塔、特斯拉电塔、居民）受损**不计入**损伤率。
  - 非防御设施 HP **不会自动恢复**，只能靠白天修复（见 6.14）。**基地升级会把核心回复至 100%（见 6.14）**，这是唯一的大额恢复手段。
- **失守 = 待收复**。判定条件：夜晚倒计时结束时，该岛**仍有敌人存活**，且该岛**防御设施全部损失**（高塔 / 特斯拉电塔 / 战斗居民 全部归零；城墙与路障不计入，因为它们不输出伤害）。
- **非防御设施** = 基地核心、仓库、居民住房、码头、自动发电厂、自动采集机、自动维修机。
- **完美防御（单岛单夜）** = 当晚该岛**非防御设施全部未受到任何伤害**，且该岛未失守。
- **夜末残敌的处理（未失守的情况）：** 若该岛**防御设施仍有存活**，剩余敌人**撤退回海**。**只有失守的岛才会把残敌留到白天**（见 4.6）。

### 4.2 失败：主岛核心爆炸 / 玩家死亡

- **触发（任一立即失败）：**
  1. **主岛核心 HP 归零**（任何时候）；
  2. **玩家 HP 归零**（任何时候）；
  3. **第 10 夜任一岛屿失守**。
- **不是失败的情况：**
  - 防御设施、城墙全毁 → 不失败，只要核心还在。
  - **副岛失守** → 不失败，进入"待收复"（见 4.6）。
- **后果：** 当前画面立即中断 → BE 结局演出 → 存档选择界面。

### 4.3 胜利：撑过第 10 夜且无岛失守

| 结局 | 条件 | 内容 |
|---|---|---|
| **NE（普通胜利）** | 撑过第 10 夜，无岛失守 | 主结局演出 |
| **HE（完美胜利）** | 撑过第 10 夜，无岛失守，**且第 10 夜结算时每座岛的损伤率均 ≤ 20%** | 主结局演出 + 完美结局彩蛋段 |

**HE 的 20% 是第 10 夜结算时刻的快照**，不是"整局累计受伤 ≤ 20%"。

### 4.4 完美防御（单岛单夜奖励）

- 逐**岛**、逐**夜**独立判定。条件：当晚该岛**非防御设施没有受到任何伤害**，且未失守。
- 奖励（详见 7.7）：

| 奖励 | 概率 / 条件 |
|---|---|
| 该岛次日产出 +10%（当日有效） | 100% |
| 该岛全体居民信赖 +1 | 100% |
| 漂流居民（随机事件） | 首次必定，之后每次 25%，达到居民上限则不触发 |

- **不提供研究点。** 研究点只有两个来源（6.12 岛屿升级、6.13 玩家等级）。
- **防止读档刷取：** 奖励由 `(天数, 岛屿ID)` 确定性生成，同一存档读档重打同一夜结果不变。

### 4.5 结局流程

```
玩家死亡 / 主岛核心爆炸 / 第10夜失守
    → BE 演出（3—5 屏短文本） → 存档选择界面 → 读档回到某个白天早晨

第10夜全部波次清空（且无岛失守）
    → 判定 HE / NE → 结局演出 → 结算面板
```

### 4.6 副岛失守与收复

| 阶段 | 状态 | 规则 |
|---|---|---|
| 失守当夜 | 待收复 | 结算面板标记"失守"；岛上保留残敌，**数量上限 5 只** |
| 次日白天 | 待收复 | 该岛**不产出资源**；岛上居民躲入防空洞，不可调度、不消耗食物；防御设施残骸保留 |
| 收复动作 | 待收复 → 已收复 | ① 玩家抵达该岛 → ② 清剿 ≤5 只残敌 → ③ 把核心修到 **100%**（修复无时间、无每日上限） |
| 收复后 | 已收复 | 居民自动归队（1 秒演出）；该岛恢复产出；防御设施残骸需要玩家重建 |

**收复耗时预算：** 航行 5 秒 + 清剿 10—15 秒 + 修满 0 秒 + 归队 1 秒 = **约 16—21 秒**，远小于半天（50 秒）。

- 残敌保留其**当前 HP**。
- 修复到 100% 的材料：`木 0.4 + 石 0.2 / HP × 岛屿等级系数`。
- **待收复状态不受每日 25% 修复上限约束**。
- 若到第 10 夜仍未收复，该岛在 BOSS 夜失守 → 直接判负。

## 5. 单局流程与状态机

```
Boot → MainMenu → SaveSelect → Day ⇄ Travel
                                  ↓
                              Night → Result → NextDay → Day
                                 ↓
                  (主岛核心爆/玩家死亡/第10夜失守) → BE → SaveSelect
                  (第10夜清空)                    → Victory(NE/HE) → Result
```

| 状态 | 进入条件 | 主要行为 | 退出条件 |
|---|---|---|---|
| MainMenu | 启动 | 新游戏 / 继续 / 读档 / 设置 | 选择后进入 |
| SaveSelect | 主菜单或 BE 后 | 展示最多 10 个存档槽 | 选中某个存档 |
| Day | 新一天开始 | 采集、下令建造、修复、升级、调度居民与上塔、点树、跨岛移动、**存档** | 白天倒计时结束（100 秒） |
| Travel | 白天或夜晚在码头出发 | 航行倒计时（不可操作） | 倒计时结束 |
| Night | 入夜转场结束 | 所在岛实时战斗；**清场后可采集/建造/修复，不可拆除**；其他岛同模型无画面演算 | 夜晚倒计时结束（80 秒）／出现失败条件 |
| Result | 夜晚结束 | 分岛结算 | 玩家确认 |
| NextDay | 结算确认 | 天数 +1；自动存档；处理待收复岛状态 | 进入 Day |
| BE | 主岛核心爆 / 玩家死亡 / 第10夜失守 | 失败演出 | 玩家确认 → SaveSelect |
| Victory | 第 10 夜清空 | NE / HE 判定与演出 | 结算面板 → 回 MainMenu |

**状态约束：**

- **只有 Day 状态可以存档**（含自动存档）。
- Night 内部有子状态：`PlayerIslandRendered` 与 `RemoteIslandHeadless`，并行运行。
- Result 是叠加在"第 N+1 天清晨场景"上的暂停面板。

## 6. 系统设计

### 6.1 玩家与交互

| 项目 | 规则 |
|---|---|
| 视角 | 2D 俯视（正交） |
| 移动 | WASD / 方向键；鼠标点击建造与交互 |
| 采集 | 走到资源点旁按住交互键，持续采集 |

6. 每个敌人出生点到基地核心**必须始终存在一条可通行路径**；会封死通路的放置无法确认。

### 6.5 高塔：空塔是墙，站人成塔

| 状态 | 表现 |

### 6.7 敌人与战斗

#### 6.7.1 敌人

| 敌人 | HP | 伤害 | 攻击间隔 | 攻击范围 | 移速 | 索敌 |
|---|---|---|---|---|---|---|
| 侵蚀兽（普通） | 30 | 5 | 1.0s | 接触 | 60 px/s | 统一索敌（见下） |
| **远程体（远程）** | 20 | 8 | 1.2s | **90 px** | 80 px/s | **塔 → 墙 → 其他建筑** |
| 重壳（高血） | 80 | 10 | 1.2s | 接触 | 45 px/s | 统一索敌；对建筑伤害 ×1.5 |
| 巢母（BOSS） | 600 | 20 | 1.5s | 接触 | 35 px/s | 统一索敌；每 12 秒召唤 3 只侵蚀兽 |

**索敌机制（参照《明日方舟·生息演算》的"阻挡优先 + 范围内优先级"）：**

所有敌人按同一套规则选目标：

```
1. 若被阻挡（贴着一段可阻挡物）→ 攻击该阻挡物
2. 若有攻击范围（远程体 90px）→ 在范围内按优先级挑目标：
      优先级 A：高塔（有人的）/ 特斯拉电塔     ← 防御输出设施
      优先级 B：城墙 / 高塔（空或有人的）/ 路障 ← 阻挡物
      优先级 C：其他建筑（核心、仓库、住房、码头、发电厂、采集机、维修机）
3. 范围内没有目标 → 沿最短路前进
4. 抵达核心接触距离 → 攻击核心
```

**这条规则带来的三个后果：**

1. **城墙能挡远程体。** 远程体不会无视城墙，而是**优先拆它范围内的墙**。
2. **塔会被优先集火。** 高塔/特斯拉是远程体的头号目标，"把塔放在墙后面"有意义。
3. **近战怪无法被引导去打塔**，它们只会撞上最靠前的阻挡物。

- **出生点：** 每岛 2—4 个固定入口（朝向深海的海岸）。
- **寻路方案（为什么不做 A\*）：**
  - 每岛预置一张**路点图**（12—20 个路点），手工摆放在地形要道与入口处。
  - 敌人用**最短路（Dijkstra）**在路点图上移动，路点之间直线通行。
  - 路点之间的直线上若有阻挡物（城墙/高塔），敌人在阻挡物前停下攻击，**不绕行**。
  - **路障**不参与阻挡判定，只把相邻路径段代价乘 4。
  - 12—20 个点的 Dijkstra 每帧几百次运算，比 A\* 便宜得多。**A\* 不做。**
- **固定难度：** 波次不套公式，直接按 7.2 的天数表填死。

#### 6.7.2 战斗与伤害

- 伤害结算：`伤害 = 基础伤害 × (1 + 加成) × (1 − 减免)`，无暴击、无属性克制。
- 玩家与居民受到的减免来自护甲；建筑不减免。
- 反馈：伤害数字、命中闪光、受击红闪、建筑受击裂纹、塔弹道、拆除音效。
- 玩家攻击带武器对应的击退（对远程体同样有效）。

### 6.9 多岛夜晚（核心机制）

#### 6.9.1 基本规则

- 每个夜晚，**已解锁的岛同时受袭**。
- 玩家**只能物理上处在一座岛**，那座岛被完整渲染并可操作。
- **其他岛跑的是同一套模拟**，只是不渲染、不接收玩家输入。**没有"抽象模型"，也没有折算。**
- **不做快进播放，不做画中画，不做分屏。**

#### 6.9.2 为什么是"同一套模拟"

1. 两套模型一旦存在，就必须定义"切岛时如何把抽象结果还原成实体敌人"，必然出现敌人数取整误差、推进距离丢失、弹道与冷却丢失。
2. 一套模型下，切岛只是**打开或关闭渲染**，状态天然守恒。
3. "玩家挂机"与"玩家不在场"是同一个东西，平衡只需调一遍。

#### 6.9.3 实现规格

```
GameLoop: 固定 20Hz 逻辑 tick（与渲染帧率 60FPS 解耦，用累加器）
├─ IslandWorld[主岛]    tick(1/20) 渲染=开  输入=开
├─ IslandWorld[副岛A]   tick(1/20) 渲染=关  输入=关
└─ IslandWorld[副岛B]   tick(1/20) 渲染=关  输入=关

每个 IslandWorld 内部完全相同：
  敌人（位置、血量、目标、冷却、射程、索敌优先级）
  建筑（占地、血量、等级、冷却、弹道、建造进度、驻守者、电力占用、是否视作城墙）
  居民（位置、血量、岗位、技能、装备、所在塔）
  波次游标
```

- **远端降频：** 连续 5 秒无玩家且无通讯时降到 5Hz。
- **性能预算：** 三岛合计敌人 ≤ 120、建筑 ≤ 45、居民 ≤ **40（全居民流峰值）**。20Hz 下单帧逻辑预算 < 3ms。
- **确定性要求：** 同一存档、同一夜，重放两次结果必须完全一致。

#### 6.9.4 玩家切换岛屿

- 抵达：该岛 `渲染=开`，相机跟随，输入接管。**不需要任何状态重建**。
- 离开：切回 `渲染=关`，继续跑。
- 因为模型相同，切岛再切回来时敌人是连续演化的。

#### 6.9.5 交通（Travel）

| 场景 | 耗时 |
|---|---|
| 白天跨岛 | 5 秒 |
| 夜晚跨岛 | 7 秒 |

- **交通不是传送。** 支援 = 玩家本人过去。

### 6.10 通讯与预警

**通讯塔不是独立建筑，而是"高塔 + 通讯兵"。**

| 等级 | 解锁方式 | 能看到什么 |
|---|---|---|
| 通讯 0 | 默认 | 只知道自己所在岛。其他岛：白天只知道"有无敌袭"，夜间完全失联 |
| 通讯 1 | 主岛基地 ≥ 2 级 + 有 1 座**通讯塔**（高塔驻 ≥1 名通讯兵） | 远程查看其他岛：**非防御设施 HP 条、波次进度、状态标签（正常 / 告急 / 失守）**；黄昏时段可看到当晚大致波次档位 |

- **只有两级：0 和 1。** 本版取消了原有的"通讯 2"（失守倒计时、告急弹窗、支援推荐）——所有信息改为**常驻侧栏数据**，玩家自己看、自己判断要不要走。
- **告急的呈现方式：** 该岛 HP 条降到 35% 以下时，状态标签变红并闪烁，同时侧栏该行有一个持续脉动的光效。**没有自动弹窗。**
- **通讯 1 的获取路径：** 科技节点 2（高塔）+ 居民树节点 2（协同 Ⅰ → 通讯兵）+ 主岛 2 级。**只有混合流会达成。**
- **全居民流与全科技流没有通讯塔，全程盲打。**
- 通讯塔被摧毁（高塔被拆）或通讯兵全部下塔：该岛通讯等级**立即降为 0**，直到重新有通讯兵上塔。

### 6.11 居民系统

#### 6.11.1 剧情前提（第 1—2 天的引导链）

| 时间 | 剧情 | 收益 |
|---|---|---|
| 第 1 天 0—40 秒 | 跟随脚印 → 撬开倒塌的屋梁 → 救出**工匠** | 第 1 名建造生产类居民；开启建造菜单 |
| 第 1 天 40—100 秒 | 建造教学：**建城墙** → 把工匠放上去 → 入夜 | 1 段可用的墙；理解"建造必须有居民在场" |
| **第 2 天白天（前 50 秒）** | **居民调度教学**：发现倒塌的聚落 → 救出 **3 名居民**（1 建造 + 2 战斗）→ 解锁「居民调度」页签 → 教学：把 2 名放到战斗、1 名放到采集 | 居民总数 **4 名**；**战斗居民第 2 天起可用** |

- **在找到建造居民之前，玩家无法建造任何建筑。**

#### 6.11.2 三类职业与解锁节奏

| 类别 | 解锁来源 | 时间 | 定位 |
|---|---|---|---|
| 建造生产 | 第 1 天剧情 + 第 2 天剧情 | 第 1 / 2 天 | 开启建造菜单、建造/修复加速、现场施工 |
| 战斗 | **第 2 天居民调度教学** | **第 2 天** | 上塔变弓箭塔、地面战斗、可装备 |
| 资源收集 | **第 2 天居民调度教学** | 第 2 天 | 采集加成、被动产出 |

- **战斗类分两个子职业：近战兵 与 远程兵**，比例 **1:1**（发放时交替）。
- **一天只能解锁一个岛屿：** 第 2 天解锁第一座副岛，第 3 天解锁第二座。
- 第 2 天结束时玩家至少拥有 **2 建造 + 2 战斗 = 4 名居民**。

#### 6.11.3 居民属性与规则

| 项目 | 规则 |
|---|---|
| 成长 | **居民等级 = 信赖度**，0—5 级。每级该居民效率 +8% |
| 信赖获取 | 在岗工作每天 +0.2；参与夜间防御每夜 +0.3；完美防御 +1 |
| 维护 | 每人每天 1 食物；食物不足 → 次日效率 −50%（**不会死亡、不会离开**） |
| 撤退 | 战斗居民 HP 归零时判定为**撤退**：立即退出战场、不可再被攻击。次日消耗 `HP 损耗 × 2` 的食物复原 |
| 装备 | 战斗居民可装备武器与护甲（弓箭/弩/皮甲/铁甲/精铁甲） |
| 技能 | **每人 1 个被动技能**，内容由其在「居民调度」里分配的岗位决定（采集/研究/建造修复/驻守/通讯/闲置 各对应一个被动） |
| 岗位 | 采集 / 研究 / 建造修复 / **驻守高塔** / **通讯塔** / 闲置 |
| 地点 | 居民**绑定在具体岛屿**。跨岛调动需乘船，耗时同交通 |

- **上塔 ≠ 地面驻守。** 上塔的居民驱动塔的输出，自身不再单独行动，直到塔被摧毁。
- **英雄不可上塔。**

#### 6.11.4 居民池（保证不依赖随机）

| 来源 | 数量 | 说明 |
|---|---|---|
| 第 1 天剧情 | 1（建造） | 固定 |
| 第 2 天教学 | 3（1 建造 + 1 战斗近战 + 1 战斗远程） | 固定 |
| 副岛 A（首座） | 2（资源收集） | 固定 |
| 副岛 B（第二座） | 2（1 战斗近战 + 1 战斗远程） | 固定 |
| 居民树节点 2 / 3 / 4 / 5 / 6 | **+2 战斗 / +3 任意 / +3 任意 / +4 战斗 / +6（3 战斗）** | 固定，不随机 |
| 漂流居民 | 完美防御奖励：**必定获得 1 名**，另有 25% 概率额外获得 | 达到上限则不触发 |

- **剧情 8 名 + 居民树 18 名 = 确定性获得 26 名居民**，其中战斗类 **13 名**（近战/远程约各半），加上 **2 名英雄**共 15 名可战人口。
- **全局上限**：12 → 20 → 30 → **40**。
- **所有"战斗居民"发放时按近战:远程 = 1:1 交替**；居民树节点 6 解锁后，**任意居民可随意分配职业**（可在近战/远程之间自由转）。
- **全居民流的终局编制（第 10 夜）：**

| 岛屿 | 配置 |
|---|---|
| 主岛（玩家在场） | 8 名战斗居民 + 1 名英雄 + 玩家 + 城墙 |
| 副岛 A | 3—4 名战斗居民 + 城墙 |
| 副岛 B | 3—4 名战斗居民 + 城墙（英雄） |

#### 6.11.5 居民基础数值

| 职业 | HP | 采集/建造加成 | 战斗能力 |
|---|---|---|---|
| 建造生产 | 60 | 建造速度 +60%，修复速度 +60% | 可上塔当弓兵 |
| 资源收集 | 50 | 采集速度 +50%；在岗被动：木 +1.5/秒 或 石 +1.0/秒 或 食物 +2.0/秒 | 可上塔当弓兵 |
| **战斗·近战** | **150** | — | 近战：伤害 **5**，间隔 **1.0 秒**，射程 **10 px**；可装备护甲 |
| **战斗·远程** | **80** | — | 远程：伤害 **8**，间隔 **1.2 秒**，射程 **70 px**（可换装备）；**上塔时按"弓箭塔精锐"计算** |
| **英雄·近战** | **300** | — | 近战：伤害 **48**，间隔 **2 秒**，射程 **10 px**；**击技**：每攻击 3 次触发一次小范围 AOE（半径 20 px，伤害 48）；**不可上塔** |
| **英雄·远程** | **200** | — | 远程：伤害 **24**，间隔 **0.8 秒**，射程 **50 px**；**驻守的岛全体战斗居民伤害 +40%**；**不可上塔** |

- 英雄一近一远成对发放（居民树节点 6 的"2 名英雄"= 1 近战 + 1 远程）。

### 6.12 基地等级

| 岛屿 | 等级 | 核心 HP 上限 | 塔上限 | 岗位槽 | 升级消耗 | 门槛 | 奖励 |
|---|---|---|---|---|---|---|---|
| 主岛 | 1 | 200 | 2 | 2 | 初始 | — | — |
| 主岛 | 2 | 280 | 3 | 3 | 80 木 + 40 石 | — | **+3 研究点** |
| 主岛 | 3 | 380 | 4 | 4 | 150 木 + 90 石 | 累计研究点 ≥ 8 | **+4 研究点** |
| 主岛 | 4 | 500 | 5 | 5 | 250 木 + 160 石 | 累计研究点 ≥ 20 | **+4 研究点** |
| 副岛 | 1 | 150 | 2 | 1 | 解锁即 1 级 | — | **+1 研究点** |
| 副岛 | 2 | 300 | 3 | 2 | 150 木 + 90 石 | **主岛 ≥ 3 级**，累计研究点 ≥ 8 | **+1 研究点** |

- **研究点合计：3 + 4 + 4 + 1 + 1 + 1 + 1 = 15 点。**
- **副岛升级贵是故意的。** 成本与主岛升 3 相同，且**必须先把主岛升到 3 级**。
- **"累计研究点"门槛：** 本局**累计获得**的研究点总量，不消耗余额。
- **库存联动：** 主岛升 4 需 250 木，主岛 3 级时上限 220，因此**必须至少建 1 座仓库**（260）。
- **岗位槽 + 住房：** 每岛可容纳居民数 = 基地等级岗位槽 + 居民住房数 + 居民树节点 3 的 +2。
- **升级会把核心 HP 直接回复至 100%**（见 6.14）。

### 6.13 玩家等级

| 等级 | 累计 XP | 奖励 |
|---|---|---|
| 1 | 0 | 初始 |
| 2 | 40 | +1 研究点 |
| 3 | 100 | +1 研究点 |
| 4 | 180 | **+3 研究点**（含里程碑 +2），HP 上限 +10 |
| 5 | 280 | +1 研究点 |
| 6 | 400 | +1 研究点 |
| 7 | 540 | **+3 研究点**（含里程碑 +2），HP 上限 +10 |
| 8 | 700 | +1 研究点 |
| 9 | 880 | +1 研究点 |
| 10 | 1080 | **+3 研究点**（含里程碑 +2），HP 上限 +10 |

- **玩家等级合计 15 研究点**；**岛屿升级合计 15 研究点**。两者相加 = **30 点 = 恰好点满一棵树**。

**XP 来源：**

| 事件 | XP |
|---|---|
| 击杀侵蚀兽 / 远程体 | +2 |
| 击杀重壳 | +5 |
| 击杀巢母 | +40 |
| 完成一次建造 | +3 |
| 完美防御（每岛每夜） | +15 |
| 收复一座岛 | +25 |
| 存活过一夜 | +10 |

**"30 点 = 一棵树"的设计含义：**

- 若玩家等级给得远多于岛屿升级，玩家会不升岛（省材料去建塔）——研究点照样够，基地等级沦为只加核心 HP 的鸡肋。
- 若岛屿升级给得远多于玩家等级，等级系统变成摆设。
- 两者各 15 点、合计正好等于一棵树的价钱，使得：**不升岛 = 少一半研究点 = 点不满任何一棵树**，两条线互为前提。

### 6.14 维护、修复与损伤

**损伤率** = 非防御设施总 HP 的缺失比例（见 4.1）。

**非防御设施修复（白天）：**

| 项目 | 规则 |
|---|---|
| 位置要求 | 玩家必须在该岛，站在受损建筑旁 |
| 耗时 | **0 秒**（点击即完成） |
| 消耗 | 每修复 1 点 HP：木 0.4 + 石 0.2，再乘岛屿等级系数 |
| 等级系数 | 主岛 1/2/3/4 = ×1.0 / ×1.2 / ×1.4 / ×1.6；副岛 1/2 = ×0.8 / ×1.0 |
| 每日上限 | 每岛每天最多修复 该岛非防御设施总上限的 **25%**（**待收复状态不受此限**） |

**基地升级的回血效果（重要）：**

- **基地升级完成时，核心 HP 直接回复至 100%**（不是按百分比保留）。
- 这是本作唯一的"大额恢复"手段，一局最多用 6 次（主岛 3 次 + 副岛各 1 次）。
- 它让"升 4 级"同时是一个战略回血点，也意味着**损伤管理的核心是"把损伤拖到你本来就打算升级的那一天"**。

**自动维修机（科技 6 的可建造设施）：**

- **每天凌晨自动修复本岛所有受损设施**，每个设施耗时 3 秒（串行），**消耗材料**，耗电 1。
- 只修建筑，**不修居民、不复活撤退居民**。
- 材料不足时按顺序修，修到材料耗尽为止，并提示缺什么。

**战斗居民恢复：** 次日消耗 `HP 损耗 × 2` 的食物即可复原。

**防御设施黎明维修：** 若本岛没有自动维修机，受损防御设施不会自动修复，只能靠玩家手动修。

## 11. 技术方案

### 11.1 引擎与工程

- **引擎：** Godot 4.x，GL Compatibility 渲染器。
- **语言：** GDScript；第一版不做 GDExtension。
- **导出：** Web（HTML5），关闭多线程导出。
- **部署：** 魔搭创空间静态托管，产出 `index.html` + `index.pck`。

### 11.2 主循环与多岛演算

```
Godot 主场景
└─ GameRoot (Node)
   ├─ TickAccumulator        固定 20Hz 逻辑推进
   ├─ IslandWorld[MAIN]      Node2D，渲染开关 = true
   ├─ IslandWorld[SUB_A]     Node2D，渲染开关 = false
   ├─ IslandWorld[SUB_B]     Node2D，渲染开关 = false
   └─ UILayer
```

**关键约定：**

- 三个 `IslandWorld` 是**同一个场景的实例**，代码路径完全相同，只有 `visible` 与 `input_enabled` 不同。
- **禁止**在 `IslandWorld` 里写 `if island_id == MAIN` 这类分支。所有差异走数据表。
- 固定 20Hz 用累加器，单帧最多补 4 步。

**接口：**

```gdscript
class_name IslandWorld extends Node2D

var island_id: String
var base_level: int
var core_hp: float
var core_hp_max: float
var buildings: Array[BuildingState]
var residents: Array[ResidentState]
var enemies: Array[EnemyState]
var wave_cursor: int
var power_used: int
var power_capacity: int
var render_enabled: bool
var input_enabled: bool
var occupancy: Dictionary      # Vector2i -> building_id，占地索引

func tick(dt: float) -> void
func apply_player_input(cmd: InputCommand) -> void
func snapshot() -> Dictionary
func restore(data: Dictionary) -> void
func set_active(active: bool) -> void
func can_place(def_id: String, origin: Vector2i) -> bool   # 7 条校验
func occupy(building_id: String, origin: Vector2i) -> void
func release(building_id: String) -> void
func recompute_tower_forms() -> void
func recompute_wall_links() -> void
func recompute_power() -> void
```

### 11.3 性能目标

| 指标 | 目标 |
|---|---|
| 渲染帧率 | 60 FPS（当前岛） |
| 三岛逻辑 tick | 单帧 < 3ms（20Hz） |
| 三岛合计敌人上限 | 120 |
| 建筑上限 | 45 / 岛 |
| **居民上限** | **40 全局** |
| 占地检查 | 每次放置 O(占地格数)，不做全图扫描 |
| 首屏加载 | < 15 秒 |

### 11.4 已知技术风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **占地索引与连通性双重重算** | 放置/拆除要同时更新占地 Grid 与墙体连通 | 两个独立入口 `occupy/release` 与 `recompute_wall_links`，都在建造/拆除/摧毁时同步调用 |
| **高塔 3 人同塔** | 3 个独立计时器 + 3 条弹道，塔毁时 3 种不同处理（近战落地、其余撤退） | 把"驻守者"做成塔的子实体数组，统一由 `recompute_tower_forms()` 重算 |
| **40 名居民的模拟开销** | 全居民流峰值 40 人 × 3 岛 | 居民逻辑极简化（无寻路，定点工作）；只在被攻击或上塔时参与战斗计算 |
| 统一索敌的复杂度 | 每只敌人每 tick 要做一次范围内优先级筛选 | 空间网格 + 每 0.25 秒重选一次目标 |
| 电力优先级 | 容量变化时决定停谁 | 固定优先级数组，统一重算 |
| 三岛同跑性能 | 峰值 120 敌人 | 远端降频 5Hz；对象池 |
| 存档序列化 | 三岛 + 40 居民 + 每建筑占地坐标 | 只存必要字段；`user://` 落 IndexedDB |

## 13. 测试计划

### 13.1 内部测试

- 每日构建自测：完整跑一遍前 3 天流程。
- 每周一次全 10 天通关。
- **确定性测试：** 同一存档跑两遍，结果完全一致。
- **守恒测试：** 玩家从岛 A 移到岛 B，岛 A 的最终损伤与"玩家全程不在岛 A"完全一致。
- **收复时限测试：** 失守到收复 ≤ 30 秒。
- **形态测试：** 空塔 / 弓箭塔 / 通讯塔 / 火炮塔 / 迫击炮阵列 × 3 等级数值正确；3 人满塔输出 = 单人 × 3。
- **连通性测试：** 拆掉一段墙后，原本视作城墙的空塔应立刻变回"孤立塔楼"；**有人的塔在任何情况下都视作城墙**。
- **占地测试：** 3×3 核心外扩 1 格禁建；2×2 建筑不可跨界；城墙可 1 格拼接；拆除后占地释放。
- **索敌测试：** 远程体的目标顺序必须是 塔 → 墙 → 其他。
- **独立性测试：** 只点科技 5/6 时不应出现任何火炮塔/迫击炮阵列形态；只点居民 5/6 时不应解锁任何兵种；**三种路线各自点满 30 点时，另两方必须是零投入**。
- **研究点总量测试：** 一局可获得的研究点必须**恰好为 30**。

### 13.2 外部测试（第 3 周中段，3—5 人，不先教学）

**必须验证的 10 个问题：**

1. 玩家是否理解"我只有一个身体，其他岛靠设施守"？
2. 玩家看到侧栏某座岛变红闪烁时，**会不会真的坐船过去**？
3. 玩家是否理解"我在场 / 我不在场"的防御力差异？
4. 玩家是否说得清科技树与居民树的区别，**以及协同是什么**？
5. 玩家是否理解"要把 30 点全投一棵树"这件事？（如果他说"我随便点点"，说明路线教学失败）
6. 第 2 天首次副岛遇袭时，玩家是否觉得"惊险但可理解"？
7. 玩家死亡是否只发生在"可归因的失误"上？
8. 玩家是否理解"空塔 = 墙、上人 = 塔、3 人 = 满编"？
9. 玩家第一次遇到远程体时，是否理解"它会先拆我的塔和墙"？
10. 居民调度页签在 30+ 居民的后期是否还能用？

### 13.3 Bug 分级

- **阻塞：** 崩溃、无法读档、状态卡死、三岛模拟不同步。
- **严重：** 失守判定错误、玩家死亡判定错误、存档损坏、无法切岛、塔形态错乱、占地重叠、连通性重算错误、电力停摆错误。
- **一般：** UI 错位、数值异常、音效缺失。
- **体验：** 手感、提示文案、镜头。

### A.3 统一索敌伪代码（唯一实现，所有敌人共用）

```gdscript
func pick_target(enemy) -> Target:
    # 1. 被阻挡优先
    if enemy.blocker != null:
        return enemy.blocker

    # 2. 有射程 → 范围内按优先级
    if enemy.attack_range_px > 0:
        var cands = spatial_grid.query(enemy.pos, enemy.attack_range_px)
        for tier in [TIER_A_TOWER, TIER_B_WALL, TIER_C_BUILDING]:
            var best = nearest_in(cands, tier)
            if best != null:
                return best

    # 3. 无目标 → 沿最短路前进
    return null
```

- **TIER_A_TOWER**：有驻守者的高塔、特斯拉电塔
- **TIER_B_WALL**：城墙、高塔（空塔与有人的都算）、路障
- **TIER_C_BUILDING**：其余所有建筑（**码头除外**，码头不进入候选）

### A.4 放置校验伪代码（`can_place` 的唯一实现）

```gdscript
func can_place(def_id: String, origin: Vector2i) -> bool:
    var d = BuildingDefs[def_id]
    # 1. 全部格子在可建造区内
    if not in_build_area(origin, d.footprint_w, d.footprint_h): return false
    # 2. 不与已有建筑重叠
    if occupancy.has_any(origin, d.footprint_w, d.footprint_h): return false
    # 3. 不与资源点重叠（采空后可建）
    if resource_nodes.overlaps(origin, d.footprint_w, d.footprint_h): return false
    # 4. 核心 3×3 + 外扩 1 格禁建
    if core_forbidden_zone().intersects(origin, d.footprint_w, d.footprint_h): return false
    # 5. 码头外扩 2 格禁建
    if dock_forbidden_zone().intersects(origin, d.footprint_w, d.footprint_h): return false
    # 6. 每个敌人出生点到核心仍有可达路径
    if not path_exists_after(origin, d.footprint_w, d.footprint_h): return false
    # 7. 不覆盖路点格
    if waypoints.overlaps(origin, d.footprint_w, d.footprint_h): return false
    return true
```
